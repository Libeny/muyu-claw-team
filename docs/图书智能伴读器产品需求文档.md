# 图书智能伴读器产品需求文档

状态：草案
最后更新：2026-05-28
语言：中文

## 一、产品概述

图书智能伴读器是一款面向苹果电脑的阅读应用，核心能力是在舒适的书本阅读界面旁，提供一个可以随时召唤的智能伴读侧边栏。

这个产品不是“又一个翻译软件”，也不是“又一个文档问答工具”。它的核心是：用户保持在书本阅读状态中，右侧智能体能够理解当前页、选中文本、用户标注、附近图片、章节上下文，以及整本书和其他书之间的关联。

产品需要让用户完成这些事情：

1. 在安静、接近真实书本的界面里阅读。
2. 针对正在阅读的具体位置向智能体提问。
3. 对单词、短语、句子进行上下文翻译，并保存到生词本。
4. 将有价值的智能体对话保存为书中的“会话书签”。
5. 生成章节概要、核心观点和思考问题。
6. 将阅读成果导出为标记文档笔记或智能体技能。

## 二、产品定位

推荐定位：

> 一款把每本书变成可对话、可沉淀、可复用知识空间的苹果电脑阅读应用。

不推荐定位为：

- 通用文档问答工具。
- 独立词典。
- 稍后阅读应用。
- 纯笔记应用。
- 完整知识库替代品。

产品最强的差异化来自五个能力的组合：

- 书本原生阅读体验。
- 可召唤的智能体侧边栏。
- 当前页、图片、标注、章节共同构成的多模态上下文。
- 会话书签。
- 可导出的知识成果。

## 三、用户问题

用户在读书时，经常需要在书、词典、翻译工具、聊天式人工智能、笔记软件和复习工具之间来回切换，阅读上下文很容易断裂。

典型问题包括：

- “这个词在这句话里到底是什么意思？”
- “作者为什么在这里这么说？”
- “这张图、表格或示意图想表达什么？”
- “这段话和本章主旨有什么关系？”
- “这个观点是否在其他书里也出现过？”
- “我上次在这里和智能体讨论了什么？”
- “怎样把这段阅读收获变成以后可复用的笔记或技能？”

现有工具可以解决其中一部分，但大多数没有把人工智能对话固定回书里的具体位置。

## 四、目标用户

### 主要用户

1. 英文非虚构书读者
   - 需要上下文翻译和生词收纳。
   - 希望读英文原版书时不用频繁切换工具。

2. 深度阅读者和知识工作者
   - 阅读商业、哲学、设计、工程、战略等书籍。
   - 需要概要、概念索引、跨书关联和长期笔记。

3. 智能体重度用户
   - 希望把书变成未来工作中的可调用上下文。
   - 重视标记文档导出、类 Obsidian 笔记和技能生成。

### 次要用户

- 阅读教材的学生。
- 阅读论文和报告的研究者。
- 双语阅读者。
- 将书籍内容转化为内容选题、学习资料或工作框架的创作者。

## 五、核心交互模型

### 5.1 阅读界面

左侧是主要阅读区域。它应该更接近 Apple Books 或 Kindle 的书本体验，而不是文档管理软件。

预期行为：

- 单页和双页阅读模式。
- 深色、浅色、护眼色主题。
- 页面进度和章节进度。
- 文本选择。
- 图片选择。
- 高亮标注。
- 页边显示笔记、会话、生词等标记。
- 低干扰快捷键。

阅读器不能给人一种“聊天应用里塞了一个文档预览”的感觉。书本必须始终是主对象。

### 5.2 智能伴读侧边栏

右侧是可召唤的侧边栏。默认可以隐藏，需要时再打开。

侧边栏包含三个视图：

1. 提问
   - 与图书智能体实时对话。
   - 根据当前选区、页面和章节提供上下文提问。

2. 会话
   - 展示本书中所有挂靠在原文位置上的智能体对话。
   - 可以按章节、页码或概念分组。

3. 笔记
   - 展示沉淀后的笔记、生词、章节概要、图片解释和可导出卡片。

### 5.3 上下文快捷操作

用户选择文本后，应用应提供快捷操作：

- 翻译。
- 解释。
- 结合上下文解释。
- 保存到生词本。
- 针对这里提问。
- 关联到本章主旨。
- 转为笔记。

用户选择图片、截图区域、图表或示意图后，应用应提供快捷操作：

- 解释图片。
- 提取图片文字。
- 将图片与附近段落关联。
- 询问这张图为什么出现在这里。
- 将图片解释保存到笔记。

### 5.4 会话书签

智能体对话不应该只存在于一个全局聊天记录里。

每一次有价值的智能体对话，都可以成为一个挂靠在书中对象上的会话书签。

可挂靠对象包括：

- 页面。
- 段落。
- 句子。
- 图片。
- 高亮。
- 章节。
- 多个选中对象。

会话书签保存：

- 来源锚点。
- 选中文本。
- 附近页面上下文。
- 图片引用和图片文字识别结果。
- 用户问题。
- 智能体回答。
- 后续追问。
- 会话摘要。
- 用户确认后的笔记。

会话书签的目的不是记录“读到哪里了”，而是记录“用户在书的哪个位置和智能体共同思考过什么”。

## 六、竞品格局

后续竞品调研统一使用三个维度：核心交互方式、覆盖范围、付费能力。

| 产品 | 核心交互方式 | 覆盖范围 | 付费能力 | 我们的机会 |
| --- | --- | --- | --- | --- |
| Readwise Reader | 统一阅读器、高亮和智能阅读助手 | 网页文章、PDF、EPUB、订阅源、邮件简报、视频文字稿 | 订阅制，核心是稍后阅读和高亮同步 | 通用阅读很强，但不是苹果电脑原生的书本优先体验；生词学习和图片关联会话不是中心 |
| MarginNote | 文档阅读、摘录、脑图、卡片和人工智能工具 | PDF、EPUB、学习资料 | 不同平台上存在买断或订阅能力 | 功能强但复杂，更像学习软件，不像安静的书本阅读器 |
| NotebookLM | 上传资料后提问、总结和生成资料 | PDF、EPUB、文档、网页、笔记 | 随 Google 人工智能套餐变化 | 资料问答很强，但不是一个真正的阅读应用 |
| 欧路词典 | 系统级取词、划词翻译和生词本 | 任意可选文本、词典和翻译 | 基础免费，词库和高级功能付费 | 词典流程成熟，但不是懂整本书的智能伴读器 |
| Readlang 和 LingQ | 点击翻译、自动保存生词和语言学习 | 导入文本、网页内容、语言学习材料 | 免费额度加订阅增强 | 语言学习强，但书本级人工智能思考较弱 |
| Lensica 和 Reader Alive 一类产品 | 人工智能阅读伙伴和书本问答 | 覆盖范围不稳定，很多偏移动端或早期产品 | 各产品不同 | 验证了需求，但成熟的苹果电脑优先产品仍有空间 |

## 七、功能需求

### 7.1 书籍导入

应用应支持：

- EPUB 导入。
- PDF 导入。
- 纯文本和标记文档作为低优先级格式。

产品必须明确说明：受数字版权保护的 Kindle 或 Apple Books 购书，不能被直接导入。只有用户合法拥有且可读取的无版权保护文件，才适合导入。

### 7.2 书籍处理

每本书导入后，应用应创建一个本地书籍工作区：

```
图书/<书籍标识>/
  书籍.json
  章节/
  页面/
  图片/
  图片文字识别/
  高亮.json
  生词.json
  会话/
  笔记.md
  概要/
  索引/
```

处理流程：

1. 提取书籍元数据。
2. 识别章节和页面结构。
3. 按章节和页面提取文本。
4. 提取图片、图表和附近说明文字。
5. 对需要的图片区域进行文字识别。
6. 生成语义片段。
7. 生成向量索引。
8. 生成章节概要和概念提示。
9. 保存本地索引。

### 7.3 图书智能体上下文

图书智能体必须基于明确上下文回答，而不是凭空猜测。

每次回答可以使用：

- 当前页面文本。
- 当前选中文本。
- 当前选中图片或区域。
- 附近段落。
- 章节概要。
- 整本书语义搜索结果。
- 用户高亮。
- 会话书签。
- 已保存笔记。
- 生词记录。
- 在用户开启跨书搜索时，使用其他书籍中的相关片段。

回答应尽量引用或说明对应的书籍位置。

### 7.4 翻译与生词本

翻译是快捷模式，不是产品全部。

用户选择单词或短语后，应用应提供：

- 上下文翻译。
- 词性。
- 可用时提供发音信息。
- 原句。
- 中文简明解释。
- 可选的英文解释。
- 保存到生词本。
- 熟悉度状态。

生词记录应包含：

- 单词或短语。
- 来源句子。
- 书名。
- 章节。
- 页码或位置。
- 用户备注。
- 创建时间。
- 复习状态。

### 7.5 章节智能分析

每个章节应支持：

- 章节概要。
- 核心论点。
- 关键概念。
- 重要案例。
- 图片和表格解释。
- 思考问题。
- “我的理解发生了什么变化”提示。
- 可导出的章节笔记。

### 7.6 会话书签

会话是一级对象。

会话字段至少包括：

- 会话标识。
- 书籍标识。
- 锚点类型。
- 锚点位置。
- 标题。
- 来源摘录。
- 关联图片标识。
- 对话记录。
- 会话摘要。
- 标签。
- 创建时间。
- 更新时间。

会话应出现在：

- 右侧侧边栏。
- 书籍页边的小标记。
- 章节会话列表。
- 标记文档导出结果中。

### 7.7 标记文档导出

应用应支持一键导出标记文档。

导出类型：

- 全书阅读笔记。
- 章节笔记。
- 全部高亮。
- 生词本。
- 会话书签。
- 概念索引。
- 图片解释。

导出结果应兼容：

- Obsidian。
- Logseq。
- Notion 导入。
- 普通文本仓库。

### 7.8 技能导出

产品应支持将选中的书籍知识导出为智能体技能。

两种模式：

1. 本地个人技能
   - 可以引用用户本地书籍索引。
   - 可以包含用户笔记、概要和来源位置指针。

2. 可分享技能
   - 不应包含大量受版权保护的书籍原文。
   - 应主要包含用户自创摘要、概念框架和少量合规短引用。

示例导出路径：

```
.claude/skills/品牌差距品牌教练/SKILL.md
```

技能的目的不是复现整本书，而是帮助未来的智能体使用用户对这本书的理解进行推理。

## 八、Claude Code 与智能体运行时方向

推荐方向是：让右侧侧边栏具备 Claude Code 式智能体体验，但产品领域必须保持图书阅读专用。

产品不应该把原始编程智能体直接暴露给读者，而应该提供受控的图书智能体运行时。

### 8.1 运行时选项

方案一：原生接口型图书智能体。

- 直接使用 Claude 或 OpenAI 的接口。
- 应用自己负责上下文检索、工具调用和持久化。
- 更适合作为普通消费者应用打包发布。

方案二：基于 Claude Code 无界面模式或开发包的图书智能体。

- 使用 Claude Code 式运行时承载智能体循环、技能、工具协议和会话连续性。
- 增加图书阅读专用系统提示和技能。
- 通过受控工具暴露书籍上下文。
- 更适合高级用户和本地工作区场景。

推荐判断：

- 产品层面围绕“图书智能体运行时接口”设计。
- 如果需要优先降低打包和分发难度，可先支持原生接口型运行时。
- 在授权、认证和分发条件允许时，把 Claude Code 运行时作为高级模式。

### 8.2 图书智能体工具

运行时应通过工具访问书籍，而不是获得不受限制的文件系统权限。

初始工具集合：

- 获取当前页面上下文。
- 获取当前选中文本。
- 获取当前选中图片上下文。
- 搜索当前书籍。
- 搜索书库。
- 列出高亮。
- 保存高亮。
- 保存生词。
- 保存笔记。
- 创建会话书签。
- 总结章节。
- 导出标记文档。
- 导出技能。

### 8.3 系统提示方向

图书智能体应表现为：

- 阅读陪伴者。
- 上下文翻译者。
- 苏格拉底式提问者。
- 笔记提炼者。
- 跨书关联者。

它不应该：

- 假装知道自己无法访问的文本。
- 在没有来源上下文时给出不可靠总结。
- 大段复述受版权保护的原文。
- 把翻译当作唯一任务。
- 抢占阅读界面。

## 九、数据与隐私需求

产品会处理敏感的个人阅读数据。

本地苹果电脑应用要求：

- 默认本地存储书籍文件和索引。
- 允许用户删除一本书及其所有派生数据。
- 明确标记哪些操作会调用云端人工智能服务。
- 尽可能支持用户自带接口密钥。
- 避免不必要地上传整本书。

如果该能力接入当前仓库的多用户智能体系统：

- OAuth 令牌、接口密钥、浏览器资料、书籍派生缓存和服务配置必须存放在 `users/<discord_user_id>/...` 下。
- 运行包装器必须从 `MUYU_PROJECT_ROOT` 和 `MUYU_DISCORD_USER_ID` 推导用户状态目录。
- 当缺少 `MUYU_DISCORD_USER_ID` 时，运行包装器必须关闭执行，不能退回到共享目录。
- 定时任务必须使用任务所有者的用户标识作为状态所有者。

## 十、最小可行版本范围

第一版要证明“书本原生阅读加智能体伴读”的核心循环。

最小可行版本包括：

1. 苹果电脑应用外壳和书本阅读界面。
2. EPUB 导入。
3. 在不拖慢 EPUB 的前提下支持 PDF 导入。
4. 文本选择。
5. 右侧智能伴读侧边栏。
6. 针对选中文本提问。
7. 针对当前页面或章节提问。
8. 上下文翻译。
9. 保存生词。
10. 创建会话书签。
11. 章节概要。
12. 导出笔记、会话和生词为标记文档。

最小可行版本不包括：

- 完整间隔复习系统。
- 移动端应用。
- 公开技能市场。
- 协同阅读。
- 绕过数字版权保护。
- 完整本地大模型支持。
- 从 Kindle 或 Apple Books 自动购买或导入书籍。

## 十一、后续版本范围

最小可行版本之后增加：

- 图片和图表理解。
- 页面图片文字识别。
- 多本书语义搜索。
- 更丰富的会话浏览。
- Obsidian 知识库导出。
- Claude Code 运行时高级模式。
- 第一版技能导出。
- 生词复习队列。

## 十二、未来范围

后续可能能力：

- 本地模型运行时。
- 书籍知识图谱。
- 个性化阅读计划。
- 引用和出处管理。
- 一本书内部的概念演进时间线。
- 跨书观点对话。
- 语音讨论模式。
- 可分享阅读包。

## 十三、成功指标

产品指标：

- 每个活跃用户导入的书籍数量。
- 每周阅读次数。
- 每本书创建的智能体会话数量。
- 会话书签回访次数。
- 保存的生词数量。
- 生成的章节概要数量。
- 创建的标记文档导出数量。
- 用户完成第一章阅读后的留存。

质量指标：

- 回答可溯源比例。
- 用户纠错比例。
- 幻觉反馈数量。
- 翻译有用性评分。
- 导出结果有用性评分。

## 十四、待明确问题

1. 第一版应优先服务英文阅读，还是优先服务通用深度阅读？
2. 最小可行版本是否只从 EPUB 开始，还是同时支持 PDF？
3. Claude Code 运行时应作为首发能力，还是作为高级用户测试能力？
4. 导入书籍时应自动完成多少预处理？
5. 每次智能体对话是否自动生成会话书签，还是需要用户手动固定？
6. 导出的技能应先面向 Claude 生态，还是使用更通用的智能体技能格式？

## 十五、初始产品判断

最合理的产品路径是：把翻译作为重要快捷能力，而不是把翻译当作产品本身。

真正的主线是：

> 读一本书，在具体阅读位置和智能体共同思考，把这段思考保存回书里，并将沉淀出的知识导出为可复用成果。

会话书签应从第一版开始就是核心对象。它是本产品相对通用聊天、通用词典和通用文档问答工具最强的概念优势。
